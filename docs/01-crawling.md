# 01. Crawling: збір даних із сайтів виробників

Мета шару — надійно й економно отримати **сирі артефакти** (HTML, вбудований JSON, PDF, зображення) з різнорідних сайтів і покласти їх у Raw Store без втрати провенансу. Жодної екстракції характеристик тут ще немає — тільки доставка байтів.

## 1. Discovery (виявлення URL товарів)

Порядок джерел — від найдешевших і найточніших:

1. **Офіційні фіди / API виробника.** Google Merchant XML, YML (Яндекс/локальні), власний REST/GraphQL. Найкраще джерело: структуроване, легальне, стабільне. **Перевіряти першим завжди.**
2. **`sitemap.xml` та sitemap-index.** Дає повний перелік сторінок; фільтрувати по URL-патернах товарів (`/product/`, `/p/`, `/goods/`).
3. **Категорійні лістинги (пагінація).** Обхід каталогу, коли sitemap відсутній або неповний.
4. **Seed-и вручну** для складних кейсів.

**Дедуплікація URL:** канонізація (прибрати трекінг-параметри `utm_*`, сортувати query, врахувати `<link rel="canonical">`), щоб не краулити ту саму сторінку під різними URL.

## 2. Детекція рушія (CMS/framework fingerprinting)

Різні рушії потребують різних стратегій. Детектор працює по маркерах:

| Маркер | Рушій | Стратегія отримання даних |
|---|---|---|
| `cdn.shopify.com`, `Shopify.theme`, `/products/x.json` | Shopify | Публічний `.json`-ендпоінт товару — готова структура |
| `wp-content`, `woocommerce` класи | WooCommerce | REST `/wp-json/wc/`, JSON-LD |
| `bitrix`, `bx-` префікси | 1С-Bitrix | HTML-парсинг + мікророзмітка |
| `Magento`, `mage/` | Magento | GraphQL-ендпоінт, JSON-LD |
| `__NEXT_DATA__` | Next.js | Вбудований JSON у сторінці |
| `window.__NUXT__` | Nuxt.js | Вбудований JSON |
| немає маркерів, порожній `<body>` | Custom SPA | Перехоплення XHR/GraphQL або headless |

**Висновок детектора:** `render_mode ∈ {static_http, headless}` + `preferred_source ∈ {api, embedded_json, json_ld, html}`. Це маршрутизує сторінку на найдешевший робочий шлях.

## 3. Fetcher pool: два класи фетчерів

### 3.1 Static HTTP fetcher (дешевий, за замовчуванням)
- Звичайні HTTP-запити, без браузера.
- Витрати в 10–50× нижчі за headless.
- Підходить, коли дані є в HTML / embedded JSON / API.
- **TLS + HTTP fingerprint impersonation** (напр. `curl_impersonate`, `httpx` з профілями) — імітує реальний браузер на рівні рукостискання, щоб не відсіювали за JA3/JA4.

### 3.2 Headless fetcher (дорогий, за потреби)
- Playwright / Camoufox (стелс-форк Firefox) для SPA, які рендеряться лише в JS.
- **Перехоплення мережі:** замість того щоб чекати рендер DOM, слухати XHR/GraphQL-відповіді — там часто уже готовий JSON товару. Це швидше й точніше, ніж скрейпити відрендерений DOM.
- Керування ресурсами: блокувати завантаження зображень/шрифтів/аналітики, коли потрібні лише дані (економія трафіку й часу).

**Правило маршрутизації:** спробувати static → якщо ключові дані відсутні/порожні → ескалація на headless. Не запускати браузер там, де достатньо HTTP.

## 4. Обхід активного захисту (anti-bot)

Захист (Cloudflare, Akamai, DataDome, PerimeterX тощо) — реальність. Підхід — "бути схожим на звичайного користувача й не створювати навантаження", а не "ламати захист".

**Технічні засоби:**
- **Ротація проксі:** residential/mobile пул; призначення стабільного проксі на домен-сесію (session stickiness), щоб не викликати підозру стрибками гео.
- **Fingerprint-консистентність:** User-Agent, Accept-*, sec-ch-ua, TLS-профіль, порядок заголовків — усе має відповідати одне одному й реальному браузеру.
- **Rate limiting per domain:** обмеження RPS на домен, джитер між запитами, дотримання `Crawl-delay` з robots.txt.
- **Retry з експоненційним backoff** на 429/403/5xx; після N невдач — карантин домену й алерт.
- **CAPTCHA:** для легітимних кейсів — інтеграція solver-сервісу як крайній захід; але частіше правильніше знизити темп і покращити fingerprint, ніж розв'язувати капчу масово.
- **Кеш і conditional requests:** `ETag` / `If-Modified-Since` — не тягнути незмінене.

**Політика доброчесності (обов'язкова):**
- Поважати `robots.txt` і `Crawl-delay`.
- Не перевантажувати сервери виробника (адаптивний тротлінг за response time / кодами).
- Ідентифікуватись коректним User-Agent з контактом, де це доречно.

## 5. Легальний та етичний шар

Це не опція, а вимога проєкту:

- **Спершу шукати офіційний канал:** багато виробників дають фіди/API або дозволяють вивантаження — це усуває більшість ризиків.
- **ToS сайту та robots.txt:** оцінити, чи дозволений збір; при явній забороні — шукати договірний доступ.
- **Юрисдикція та тип даних:** характеристики товарів — переважно фактичні дані, але агрегація/публікація має враховувати авторське право на описи/зображення та локальне законодавство (в т.ч. sui generis право на бази даних в ЄС).
- **Персональні дані:** уникати; якщо трапляються (відгуки з іменами) — не збирати або анонімізувати.
- Тримати **реєстр джерел** зі статусом дозволу (feed/API/scrape/заборонено) і датою перевірки.

## 6. Планувальник (Fetch Scheduler)

- **Черга з пріоритетами:** нові товари > змінені > планова ревалідація.
- **Per-domain політика:** окремий токен-бакет на домен (RPS, конкурентність, проксі-пул).
- **Різні частоти для різних полів:** ціна/наявність — часто; характеристики — рідко (див. `06-quality-operations.md`, розділ пере-краулінгу).
- **Дедлайни й ретраї** з backoff; dead-letter черга для стабільно збійних URL.
- **Backpressure:** якщо downstream (extraction) не встигає — сповільнити fetch, не накопичувати нескінченно.

## 7. Raw Store (сирі артефакти)

Зберігаємо **до** будь-якої обробки — це основа ідемпотентності та реекстракції без повторного краулу:

- Об'єктне сховище (S3-сумісне) для тіла відповіді (HTML/JSON/PDF/зображення), стиснене.
- Метадані запису: `url`, `canonical_url`, `fetched_at`, `http_status`, `content_type`, `content_hash`, `render_mode`, `detected_engine`, `proxy_region`, `robots_allowed`.
- **Content hash** для дедуплікації та детекції змін між кроулами (незмінене — не переекстрагуємо).
- Ретенція raw-даних (напр. N останніх версій) для аудиту й порівняння.

## 8. Результат шару

На виході — записи Raw Store з повним провенансом фетчу. Наступний шар (`02-extraction.md`) працює **виключно з Raw Store**, ніколи не звертаючись до "живого" сайту, що робить екстракцію відтворюваною й дешевою для повторних прогонів.
